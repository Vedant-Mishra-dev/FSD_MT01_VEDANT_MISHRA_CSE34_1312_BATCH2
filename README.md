# Product Inventory Management API — Set C

A REST API built with **Node.js** and **Express.js** for the B.Tech Second Year Full Stack Development assignment (Set C). Product records are stored in a JavaScript array in server memory. **No database is used.**

## 1. Requirements

- Node.js 18 or later (LTS version recommended)
- npm (installed with Node.js)
- Postman or Thunder Client for manual API testing

Check your installation:

```bash
node -v
npm -v
```

## 2. Install and run

Open this project folder in VS Code, then run these commands in the integrated terminal:

```bash
npm install
npm start
```

The first `npm install` downloads Express and its dependencies from the npm registry. It also fills in the complete dependency entries in `package-lock.json`; keep the updated lock file when you push the project to GitHub.

The API starts at `http://localhost:3000` by default. The terminal displays a startup message. Stop the server with `Ctrl+C`.

To use another port, set the `PORT` environment variable before starting the server. For example, in PowerShell:

```powershell
$env:PORT=4000; npm start
```

## 4. API endpoints

Base URL: `http://localhost:3000`

| # | Method | Endpoint | Purpose | Success status |
|---:|---|---|---|---:|
| 1 | GET | `/api/products` | Get all products | 200 |
| 2 | POST | `/api/products` | Add a product | 201 |
| 3 | GET | `/api/products/:id` | Get one product by ID | 200 |
| 4 | PUT | `/api/products/:id` | Replace a product's editable fields | 200 |
| 5 | DELETE | `/api/products/:id` | Delete a product | 200 |
| 6 | GET | `/api/products/filter?category=Electronics` | Filter by category | 200 |

### POST and PUT request body

Select **Body → raw → JSON** in Postman or Thunder Client. Send all five editable fields:

```json
{
  "name": "Water Bottle",
  "category": "Accessories",
  "price": 299,
  "quantity": 40,
  "inStock": true
}
```

Validation rules:

- `name` and `category` must be non-empty strings.
- `price` must be a non-negative JSON number.
- `quantity` must be a non-negative whole number.
- `inStock` must be the JSON Boolean `true` or `false`, not a string.
- All five fields are required for both POST and PUT.
- The `id` is generated by the application. Do not send it in the request body.
- PUT replaces all editable fields; it is not a partial update.

### Example responses

A successful POST returns **201 Created**:

```json
{
  "message": "Product created successfully.",
  "product": {
    "id": 304,
    "name": "Water Bottle",
    "category": "Accessories",
    "price": 299,
    "quantity": 40,
    "inStock": true
  }
}
```

A validation failure returns **400 Bad Request** with a message and an `errors` array. A valid but nonexistent product ID returns **404 Not Found**. A category filter with no matches returns **200 OK** and an empty array (`[]`). Category matching is case-insensitive.

## 5. Test with Postman

An importable Postman collection is included here:

`postman/ProductInventory-Set-C.postman_collection.json`

1. Start the server using `npm start`.
2. Open Postman and select **Import**.
3. Import the collection JSON file from the `postman` folder.
4. Open the imported collection and select **Run** (Collection Runner) to execute its requests in order.
5. Review the response status and the **Test Results** tab for each request.
6. Also perform manual checks as needed and save genuine Postman screenshots in the `screenshots` folder.

The collection covers successful requests, invalid request bodies, invalid and missing IDs, case-insensitive filtering, an empty filter result and a missing filter parameter. The server's data resets when it restarts, so restart the server before a fresh collection run if you changed the initial records manually.

## 6. Run automated tests

This project also includes automated integration tests using Node.js's built-in test runner. They start the Express app on a temporary local port and do not require a database or an extra test library.

```bash
npm test
```

Check JavaScript syntax with:

```bash
npm run check
```
